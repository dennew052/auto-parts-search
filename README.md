# Клиентское приложение для поиска автозапчастей и аналогов

Клиентское веб-приложение на **React** и **Redux Toolkit** для интеграции с внешним API-сервисом проценки автозапчастей ([Favorit Parts / Фаворит Моторс](https://lk.favorit-parts.ru/static/wsprice.pdf)).

Интерфейс реализует двухэтапный сценарий подбора номенклатуры:
1. **Этап 1: Поиск производителей** — ввод каталожного номера (артикула), запрос к API и выбор бренда детали.
2. **Этап 2: Получение предложений и аналогов** — запрос с указанием артикула и выбранного бренда (`analogues=on`), отображение таблицы предложений оригинального производителя и всех найденных аналогов.

---

## 🛠 Технологический стек

- **Библиотека интерфейса**: React 18 (без TypeScript)
- **Управление состоянием**: Redux Toolkit (`@reduxjs/toolkit`, `react-redux`)
- **Стилизация**: Bootstrap 5 + Bootstrap Icons
- **Сборщик и локальный сервер**: Vite 5
- **HTTP-клиент**: Fetch API с поддержкой локального dev-проксирования и прямого fallback

---

## 📋 Функциональные возможности

### 1. Этап 1: Поиск производителей
- Поле ввода артикула с поддержкой быстрого ввода (кнопки с примерами артикулов из документации: `01089`, `7160500039S`, `0189`).
- Валидация пользовательского ввода (предотвращение пустых запросов).
- Запрос к API: `GET http://api.favorit-parts.ru/hs/hsprice/?key={KEY}&number={NUMBER}`.
- Группировка результатов по брендам:
  - Отображение карточек производителей;
  - Наименование детали;
  - Суммарный доступный остаток на складах;
  - Минимальная цена ("от ... ₽");
  - Кнопка «Выбрать» для мгновенного перехода к Этапу 2.
- Корректная обработка отсутствия результатов («Товар не найден»).

### 2. Этап 2: Получение аналогов и предложений
- Повторный запрос к API с передачей параметров: `key`, `number`, `brand` и `analogues=on`.
- Итоговая интерактивная таблица предложений с обязательными полями:
  - **Название / Производитель** (с разделением на запрошенный бренд и аналоги);
  - **Стоимость (цена)** (рассчитывается на основе актуальных цен складов с форматированием в ₽);
  - **Доступный остаток на складе** (с визуальными цветовыми бейджами наличия).
- Дополнительные возможности:
  - Фильтрация: «Все предложения», «Только выбранный бренд», «Только аналоги», «Только в наличии»;
  - Поиск в реальном времени по названию, артикулу и производителю;
  - Сортировка по возрастанию/убыванию цены, остатку и названию;
  - Модальное окно со списком складов: код склада (МСК РС, СПБ, ДМД и др.), тип (собственный/партнерский), остаток, цена на складе, дата и время отгрузки, признак невозвратности детали;
  - Возможность вернуться назад на Этап 1 и выбрать другого производителя.

### 3. Обработка состояний и ошибок
- Компоненты-лоадеры (`LoadingSpinner`) с поясняющим текстом на каждом этапе.
- Компоненты ошибок (`ErrorMessage`) с кнопкой повтора запроса (`onRetry`).
- Обработка специфичных кодов и сообщений API:
  - `Empty key!` — не указан ключ покупателя;
  - `Invalid key client!` — неверный ключ клиента;
  - `Empty number goods!` — не указан номер детали;
  - `Request quota exceeded!` — превышена квота запросов;
  - Пустая структура `goodsID: "00000000-0000-0000-0000-000000000000"` — деталь не найдена.
- Модальное окно настройки API-ключа (по умолчанию используется ключ из документации `00000000-0000-0000-0000-000000000001`, но пользователь может указать свой собственный коммерческий ключ).

## 🚀 Установка и запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/<username>/auto-parts-search.git
cd auto-parts-search
```

### 2. Установка зависимостей
```bash
npm install
```

### 3. Запуск сервера разработки
```bash
npm run dev
```
Приложение откроется по адресу [http://localhost:5173/](http://localhost:5173/).

### 4. Сборка для production
```bash
npm run build
```
Собранные оптимизированные статические файлы будут находиться в директории `dist/`.
